### SCT-02 相同请求连续或并发提交

| 项目 | 说明 |
| --- | --- |
| 已知事实 | 同一机构与请求作用范围内，P002、100 EUR、相同收款信息出现两次。另考虑两个处理线程同时查询，都尚未看到已有记录的分支。 |
| 判断依据 | 正文第 5、6.2 节：在明确作用范围内核对标识和输入，防止并发创建重复发送任务。 |

| 建议动作 | 找到并返回或查询已有业务结果；创建时使用可防止并发重复的机制，冲突的一方读取已有记录。已经发出的尝试按渠道契约核查。 |
| 禁止动作 | 每次点击都新建付款；用简单的“先查再插入”宣称已经解决并发；把相同字符串的跨机构请求合并。 |
| 待确认 | SCT-Q2：请求标识作用范围、保存期限、并发与渠道幂等约定。 |
| 文档检查结果 | 正文已补上并发窗口，能说明需要验证的实现条件；唯一约束、任务调度和渠道执行行为未运行测试。 |

### SCT-03 相同标识对应不同输入

### SCT-04 发送超时且查询未找到

| 项目 | 说明 |
| --- | --- |
| 已知事实 | P004 的发送尝试 A004 超时；随后一次查询返回“未找到”。渠道的数据可见延迟、查询范围和安全重试保证尚未提供。 |
| 判断依据 | 正文第 6.1 节：超时只反映通信结果，“未找到”需要查询契约解释。 |
| 判断 | 当前无法区分渠道未收到、处理中、已经处理但答复丢失。既不能确认付款失败，也不能认定已经到账。 |
| 建议动作 | 保留原业务和发送内容，核对查询标识、渠道账户和查询范围；按约定查询、接收通知或核对流水。指定负责人和跟进期限，符合已确认的安全重试条件后才决定重发。 |
| 禁止动作 | 换标识或换渠道直接付款；把原标识当作永久有效的幂等保证；只凭超时恢复余额；无限期搁置客户问题。 |
| 待确认 | SCT-Q2、SCT-Q3、SCT-Q5：查询语义、幂等范围与有效期、资金处理、客户沟通及升级期限。 |
| 文档检查结果 | 正文能够支持“结果未知”的判断和跟进选择；缺少渠道契约时，有依据地保留是否允许重发的决定。 |

### SCT-05 重复通知、处理中断与迟到冲突

| 项目 | 说明 |
| --- | --- |
| 已知事实 | P005 的同一渠道事件收到两次，随后又有一条含义冲突的迟到消息。分别设定三种本地情况：首次账务已完成；仅保存通知就中断；账务已提交但完成标记未保存。 |
| 判断依据 | 正文第 5、6.2 节：校验通知来源与关联，分开记录已接收、已应用和完成标记。 |
| 判断 | 消息到达次数不等于资金变化次数。重复接收时，是否补做取决于原处理实际完成到哪一步；迟到也不代表消息更旧或应覆盖当前状态。 |
| 建议动作 | 校验来源、作用范围和关联；已完成的结果不重复应用，仅接收未处理的安全恢复；账务提交情况不明时先查询账务。保留冲突消息并调查其是否为更正、不同阶段或错误关联。 |
| 禁止动作 | 每次通知都记账；看到事件曾出现便丢弃未完成处理；只凭到达顺序覆盖状态；让未经验证或跨账户消息改变余额。 |
| 待确认 | SCT-Q2、SCT-Q3：事件标识、真实性校验、状态语义、去重与账务提交的原子性或恢复机制。 |
| 文档检查结果 | 修订后的正文能够覆盖三个中断位置及迟到冲突；未模拟并发、中断、伪造回调或账务重试。 |

### SCT-08 召回被拒或未收到答复

| 项目 | 说明 |
| --- | --- |
| 已知事实 | P008 因重复发送提出 Recall，保留案件 C008。分别设定已收到否定答复，以及一直没有收款方 PSP 答复；后者的接收时间和营业日历不完整。 |
