本文承接[支付处理与异常](payment-processing-and-exceptions.md)修订 2，说明一笔支付如何关联业务记录、账务记录和外部流水，以及对不上时怎样查清原因。前一份说明的版本、来源及检查结果保持不变；其中 SCT-Q3 等机构待确认项不会因为新增本稿而自动关闭。

## 1. 范围与阅读方式

学习样例采用单一机构、单一 EUR 口径下的普通支付及相关账户记录。包括记录完整性、逐笔匹配、汇总与余额核对、重复导入、跨期与更正、客户退款关联。样例可以包含多笔单笔付款在外部账单中汇总展示，不涉及批量支付指令的发起规则。

**来源说明**只用于解释已阅读材料支持的概念及限制。其余处理步骤和字段均为**工程建议**，金额和标识均为合成示例。**待确认事项**集中保存在第 10 节。

本轮不指定机构会计准则、科目表、借贷分录、收入确认、客户余额算法或记账时点；不涉及换汇、卡清算、法定报表和客户资金保护金额计算。真实账单、客户数据、调整记录和审批材料保存在机构允许的私有环境。

## 2. 先区分这些记录

**来源说明。** ACCA 的[计算机会计系统教学说明](https://www.accaglobal.com/gb/en/student/exam-support-resources/foundation-level-study-resources/fa1/technical-articles/computerised-accounting-system.html)保留了分录、明细账户与总账等基本概念，并指出使用软件仍需要理解复式记账。该文采用考试场景，不能把其中的系统集成假设作为 EMI 的架构要求。

以下按本稿学习口径解释信息职责，不要求一类记录对应一个服务或一张表。

| 记录 | 回答的问题 |
| --- | --- |
| 业务订单 | 客户要求做什么，金额、对象和授权依据是什么？ |
| 支付处理记录 | 实际发出过哪些指令，渠道反馈了哪些阶段，发生了哪些真实外部交易？ |
| 账务分录 | 某个已确认的经济事项按什么规则记入哪些账户，金额与借贷方向是什么？ |
| 明细账或分户账 | 能否按客户、产品或账户查看已入账的明细及余额？ |
| 总账 | 明细如何按科目和期间汇总，汇总与明细是否按同一口径对应？ |
| 外部账单与流水 | 银行或 PSP 对指定账户报告了哪些条目、余额和时间信息？ |
| 对账批次 | 本次选用了哪些输入版本、规则、范围，得到了哪些匹配与差异？ |
| 差异案件 | 某个差异由谁调查，需要什么证据，是否已更正和复核？ |

业务订单、消息、分录和外部条目分别计数。一笔付款可能对应多条账务分录，一条外部汇总条目可能对应多笔交易；同一条流水也可能被通知、账单或重复下载多次展示。

## 3. 账务记录怎样关联

### 3.1 借贷平衡能说明什么

本稿以同一记账货币中的复式分录说明：一组借方 100 EUR、贷方 100 EUR 的记录满足金额平衡。完整重复记录这组分录后，借贷双方都变成 200 EUR，仍然平衡，但同一事项已经被记了两次。

因此，工程检查分别回答：分录是否平衡、是否记到了正确账户、是否有业务依据、是否重复或遗漏。银行账单的借贷标识还要按账户视角转换，不能直接套成所有内部科目的增减方向。

### 3.2 建议保存的关联

| 信息 | 建议用途 |
| --- | --- |
| 机构、账簿、账户、币种与会计期间 | 限定记录的比较范围。不同口径分开核对。 |
| 业务事件与付款标识 | 说明为什么记账，区分客户意图、发送尝试与实际交易。 |
| 分录组标识与记账操作标识 | 查明是否已提交，防止相同操作重复应用；唯一性范围由机构规则明确。 |
| 业务发生、记账、接收及外部日期 | 保留原值与时区，区分业务时间、系统时间、入账日期和起息日期。 |
| 分录行、金额、币种、借贷方向与规则版本 | 支持复算、追溯和明细汇总。 |
| 原分录、更正分录与审批引用 | 说明更正了什么、为什么更正及由谁复核。 |

已入账记录的更正建议使用可追溯的冲正或调整记录，保留原记录，具体方法与期间由财务确认。对账批次重跑只重新计算匹配和差异，不直接再次记账或付款。

若记账调用超时，先按操作标识核实是否已提交，再决定恢复动作。防重复约束、整组分录提交和完成标记之间的中断行为需要项目测试；“程序收到过事件”不证明账务已经完成。

## 4. 几种余额不能直接比较

| 余额 | 本稿中的含义 | 比较前要查什么 |
| --- | --- | --- |
| 客户账面余额 | 按选定客户账户及已入账记录计算的余额。 | 账户、币种、截点、记账规则与分录完整性。 |
| 客户可用余额 | 产品允许当前继续使用的额度。 | 预留、限制等规则；不能直接用来代替账面余额。 |
| 内部外部账户账面余额 | 机构在内部账簿中记录的某个银行或 PSP 账户余额。 | 是否对应同一个外部账户，是否包含费用、待处理项或调整。 |
| 银行或 PSP 报告的余额 | 外部针对账户、余额类型及时间报告的数值。 | 已入账还是其他类型、报告覆盖范围、入账与起息日期。 |

**工程建议。** 对已选定的单一账户，在同一币种、已入账口径与完整期间内，可以检查：期初余额加上该期间全部带方向的已入账变化，是否得到期末余额。方向先按账户视角统一；不能把跨币种金额相加，也不能把未入账记录混入已入账余额。

例如，合成外部账户期初为 1,000 EUR，期间只有一笔已入账付款造成 100 EUR 减少，期末应为 900 EUR。这是该账户的算术检查，不证明客户可用余额也是 900 EUR，也不证明收款人已经到账。

明细汇总与总账需要相同的映射、期间和完整范围。客户余额总和与某个外部账户余额即使相等，也不能据此认定客户资金保护足额；本稿未检查资金保护的范围、方法和适用要求。

## 5. 外部输入先检查完整性

**来源说明。** [EPC188-09 v5.0 第 0、1 节](https://www.europeanpaymentscouncil.eu/sites/default/files/kb/file/2025-04/EPC188-09%20v5.0%20Recommendation%20on%20Customer%20Reporting%20SCTs%2C%20OCT%20Inst%20and%20SDDs.pdf#page=3)讨论 `camt.052`、`camt.053` 和 `camt.054` 的客户报告映射。其范围限于收款侧信息，未覆盖付款人侧、R-transactions 或 Inquiry，也未提供完整使用规则。本稿只用它解释报告与交易明细的层次，未选择任何渠道格式。

**工程建议。** 导入和匹配前保留下列输入信息；渠道不提供某项时记录缺口，不能补造。

| 输入检查 | 需要保留或核对的内容 |
| --- | --- |
| 来源与范围 | 提供方、机构、账户、币种、访问授权、文件或接口版本。 |
| 文件或查询身份 | 报告标识、内容摘要、版本、更正关系、下载时间；相同文件名不等于相同内容。 |
| 覆盖范围 | 期间、时区、日期口径、分页或文件分段、最后一页标识，以及约定的完整性信息。 |
| 条目与余额 | 条目状态、原始方向、金额精度、期初期末余额类型和时间、可用的笔数与控制总额。 |
| 解析结果 | 原始内容与解析版本的关联、无法解析的条目及原因；不能静默跳过。 |

缺页、部分下载、解析失败或覆盖范围未知时，批次标记为输入不完整。成功解析一份文件、收到空列表或当前匹配数为零，都不足以证明“当期没有交易”。

待处理与已入账条目分别使用；同一经济事项后来变为已入账时保留关联，避免两次计入。通知与账单可能描述同一条目，先确认渠道的关联规则，不把多种报告的金额直接相加。

## 6. 一次对账怎样进行

**来源说明。** ACCA 的[财务报表准备流程教学说明](https://www.accaglobal.com/gb/en/student/exam-support-resources/foundation-level-study-resources/fa1/technical-articles/preparing-fin-statement.html)指出外部对账可以发现录入、分配和时间等差异。本稿不沿用其“银行未集成”等考试假设，以下步骤为作者工程建议。

1. **确定范围。** 固定机构、账簿与账户映射、币种、期间、时区、日期口径和规则版本。
2. **固定输入。** 对内部记录和外部报告保存可追溯的输入版本或查询截点，检查完整性及与前期的衔接。
3. **逐笔或按组匹配。** 按可靠引用、账户范围、金额、方向和阶段查找对应关系；多笔汇总时保留成员与分配依据。
4. **检查数量与金额。** 分别报告匹配、未匹配、重复、冲突、排除和解析失败记录；原始导入数量与分类结果能解释得通。
5. **检查余额。** 复算单一账户的期初、期间变动与期末关系，再比较口径一致的内部余额和外部余额；明细与总账另行核对。
6. **处理差异。** 为差异指定负责人、证据要求和跟进期限。需要调整时，按权限执行并保留新的分录或来源版本。
7. **复核结果。** 用新批次复查更正，保留旧结果、未决事项和复核人，明确这次能确认的范围。

“执行完成”“输入完整”“有未决差异”“已复核”表达不同事实，不能用一个“成功”覆盖全部含义。匹配出的记录可以作为候选结果；输入不完整或存在未决差异时，不能把整个范围标成已全部核对一致。

### 6.1 金额相等还不够

相同金额和日期只能帮助发现候选，不能单独作为交易身份。多对一或一对多匹配应有明确成员及金额分配；已分配金额不能在同一口径内重复使用。多个候选同样符合条件时保留歧义，不由 Agent 随意选一笔。

[EPC188-09 第 1.2、2.1 节](https://www.europeanpaymentscouncil.eu/sites/default/files/kb/file/2025-04/EPC188-09%20v5.0%20Recommendation%20on%20Customer%20Reporting%20SCTs%2C%20OCT%20Inst%20and%20SDDs.pdf#page=4)说明报告的层次和汇总展示可能依赖 PSP 与客户的约定。实际使用汇总、费用或净额匹配时，另行取得渠道契约及明细，不能由这个通用说明推定某家 PSP 的行为。

本稿的合成费用例子为同一外部账户付款本金共 300 EUR，另有经过确认的账户服务费 3 EUR，账户减少合计 303 EUR。费用单独关联费用依据；不能看到差额 3 EUR 就自动归为费用，也不能据此从收款人的付款本金中扣除 3 EUR。

### 6.2 时间与更正

内部记账日、外部入账日、起息日和收到文件的时间分别保留。只有取得依据后，才能把某项差异解释为时间差；缺少下一期数据时先留为未决，并持续跟进，不能自动移除。

账单更正、迟到条目或解析规则修复后，创建新的输入版本和对账批次，保留替代关系及受影响期间。旧结果保留其当时输入，不覆盖成新的“通过”。已关闭期间需要由财务确认是否重开或在后续期间调整，不能直接回写历史日期。

## 7. 差异怎样处理

| 差异 | 先查什么 | 处理边界 |
| --- | --- | --- |
| 内部有、外部没有 | 输入是否完整、查的是哪个账户与阶段、是否跨期、外部是否执行。 | 未查清前不重新付款，也不直接认定已失败。 |
| 外部有、内部没有 | 外部真实性、业务关联、内部是否已记账但关联丢失、是否存在未识别业务。 | 先查明归属和责任；不能为匹配虚构订单或直接给客户加款。 |
| 重复记录 | 重复导入、同一事件多份报告、重复记账还是两笔真实外部交易。 | 重复展示可避免重复应用，真实资金变化必须分别保留。 |
| 金额、方向、币种或对象冲突 | 解析映射、原始值、费用依据、账户视角和输入版本。 | 不取绝对值掩盖方向，不跨币种抵消，不用无依据的费用或调整抹平差额。 |
| 总额相等但明细不符 | 逐笔引用、收款对象、是否有抵消错误或遗漏。 | 保留明细差异，不能只凭总额关闭案件。 |
| 客户已退款，渠道后来取回资金 | 已有客户退款、原付款、渠道资金转回和相关账务处理。 | 分别关联两条处理，避免同一依据重复退款；客户责任不因渠道尚未取回而自动延后。 |

客户退款与渠道资金取回的区别沿用[支付处理与异常第 4.2 节](payment-processing-and-exceptions.md#42-渠道资金取回与客户退款)，不在本稿复制另一套法律解释。

对账发现差异时，先固定证据、评估影响并按权限调查。需要修复时记录依据、原值、修复动作、执行者、复核者和复算结果；差异解释成立与账务调整完成分别记录。采用暂记账户也不代表调查已经结束。对账程序和 Agent 默认不获得付款、退款、核销或风险接受权限。
