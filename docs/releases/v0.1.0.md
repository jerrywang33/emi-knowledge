# EMI Knowledge v0.1.0

- 版本日期：2026-09-02
- 发布级别：`engineering_baseline`
- 内容范围：DORA ICT 变更管理
- 内容摘要：`572112de29790efa365b5fd25b764ada419fde99c34ee59e38be881dfb88f3e7`

## 发布结果

`v0.1.0` 固定了 EMI Knowledge 的首条完整知识链。发布内容包括 3 个 Source、20 个 Provision、15 个 Requirement、3 个 Decision、8 个 Control 和 8 个 Verification，共 57 个对象和 147 条受控关系。

15 项监管要求覆盖两条 EMI 路径：未获 EMD2 Article 9(1) 豁免主体采用完整 ICT 风险管理框架，共 11 项；已获该豁免主体采用简化框架，共 4 项。每项要求均有关联控制，每项控制均有关联验证，8 项验证共定义 16 个证据模板。

## 检查与复现

发布前执行：

```bash
npm ci
npm run check
npm run release:v0.1
npm test
```

`npm run check` 包含 TypeScript 类型检查、自动化测试、Schema 校验和知识图校验。发布生成器在写盘前使用公开的 [`release-artifact.schema.json`](../../schemas/v0.1/release-artifact.schema.json) 校验三种机器文件。自动化测试还会根据固定配置重新生成全部发布文件，并逐字节检查仓库版本是否发生漂移。

Git tag `v0.1.0` 绑定通过最终验收的仓库状态。检出该 tag 后执行上述命令，可以复现 Manifest 中记录的内容摘要和发布文件。

## 待确认项

Manifest 显式保留 37 个 `institution_defined` 项，包括机构角色、重大变更标准、测试深度、回退测试深度、紧急变更复核时限、证据来源系统和证据保存期限。使用方需要在受控的机构私有知识层补充这些信息。

## 发布边界

本版本完成来源映射、知识模型、工程控制、检查方法、证据模板和发布流程的工程审查。审查范围未包含具体机构法律适用性、内部政策、监管往来、生产配置、真实运行证据或合规状态。

本版本不构成法律意见、监管批准、合规认证或生产就绪结论。真实机构采用前仍需由具备权限的法律、合规、风险、业务和技术责任人完成相应确认。
