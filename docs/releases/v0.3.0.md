# EMI Knowledge v0.3.0

- 版本日期：2026-09-07
- 发布级别：`engineering_baseline`
- 内容范围：DORA ICT 变更管理；ICT 事件管理、分类与监管报告；ICT 业务连续性、备份与恢复
- 内容摘要：`6adba77ba28d33c8d7ed02b13848b3bb9114f6b13209fe274bb76c53c6dbdad4`

## 发布结果

`v0.3.0` 固定了三个 DORA 专题及其共享对象：

| 专题 | 修订 | 独立闭包 |
| --- | ---: | ---: |
| `dora-ict-business-continuity-backup-recovery` | 3 | 94 个对象 |
| `dora-ict-change-management` | 1 | 57 个对象 |
| `dora-ict-incident-management-reporting` | 7 | 204 个对象 |

组合发布包含 11 个 Source、153 个 Provision、104 个 Requirement、12 个 Decision、31 个 Control 和 31 个 Verification，共 342 个对象、945 条受控关系和 62 类 EvidenceRequirement。共享对象在发布中只保存一次，243 个机构待定参数和证据配置继续作为 `unresolved_items` 显式发布。

业务连续性专题以 23 项 Requirement 为入口，建立 10 项 Control、10 项 Verification 和 20 类 EvidenceRequirement，覆盖 BIA 与依赖、政策治理、恢复目标与容量、计划生命周期、备份还原、严重中断与第三方场景、恢复完整性、测试切换、缺陷改进及启动沟通。相邻专题之间共享 Provision 表达法规联系，各 Topic 的 Requirement、Control 和 Verification 闭包保持独立。

## 待确认内容

Manifest 保留 243 个 `institution_defined` 实施项，主要包括机构角色、系统与渠道、控制参数、证据来源系统和保存期限。业务连续性专题还需要具体机构确认：

1. EMD2 Article 9(1) 豁免状态、DORA microenterprise 状态及完整或简化框架适用分支。
2. 关键或重要职能、BIA 结论、RTO、RPO、备份频率、启动阈值、恢复架构、测试参数、恢复验收标准和风险接受。
3. Malta EMI 申请使用的 AX05、Minimum Requirements Guidelines、Addendum 及可能存在的连续性材料模板的当前版本和提交范围。
4. 真实 EMI 组织、系统、连续性计划、灾备配置、演练、事件和运行证据下的业务验证结果。

## 发布边界

本版本完成来源映射、知识关系、通用工程控制、验证、证据模板、Topic 组合和固定发布的工程审查。审查范围未包含具体机构法律适用性、真实业务影响分析、生产恢复演练、恢复接受、监管提交、运行证据或合规状态。

Agent 可以提供受来源约束的分析和候选材料，不能批准框架分支、灾难声明、计划启动、恢复完成、风险接受、整改关闭或外部提交。本版本不构成法律意见、监管批准、合规认证或生产就绪结论。
