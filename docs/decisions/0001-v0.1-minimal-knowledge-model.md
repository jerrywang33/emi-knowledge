# Decision 0001：v0.1 最小知识模型

| 项目 | 值 |
| --- | --- |
| 状态 | 已接受 |
| 决定日期 | 2026-08-31 |
| 适用范围 | EMI Knowledge v0.1 DORA |
| 设计输入 | `DORA-SOURCES-2026-08-31-R2`、`DORA-LANDSCAPE-2026-08-31` |

## 背景

EMI Knowledge 的知识链包含来源、条款、监管要求、适用范围、人工决定、控制、实施规则、检查和证据九类信息职责。若把每类信息都设计成独立对象，v0.1 会增加引用、版本和状态管理成本，也会在真实内容形成前固化尚未验证的边界。

v0.1 需要先支持 ICT 变更管理的来源到证据闭环，并保留人员、Agent 和产品共同使用所需的稳定引用和治理边界。

## 决定

v0.1 使用六种核心对象：

| 对象 | 职责 |
| --- | --- |
| `Source` | 保存法规或监管文件的发布机构、标识、版本、效力、日期和官方链接。 |
| `Provision` | 保存来源文件中的精确位置和必要摘要，使后续内容能够定位到具体条款。 |
| `Requirement` | 保存从一个或多个条款拆出的单一义务、限制、条件或期限。 |
| `Decision` | 保存有权人员确认的解释、适用性决定、例外、理由和有效时间。 |
| `Control` | 保存为满足一个或多个要求而设计的治理或技术控制及其预期结果。 |
| `Verification` | 保存检查或测试方法、预期结果、失败处理和所需证据。 |

三类信息在 v0.1 中作为内嵌结构：

| 内嵌结构 | 所属对象 | 职责 |
| --- | --- | --- |
| `Applicability` | `Requirement` | 保存司法辖区、主体、牌照角色、业务活动、产品、框架分支和有效时间。 |
| `ImplementationRule` | `Control` | 保存流程、权限、数据、接口、配置、运维和异常处理规则。 |
| `EvidenceRequirement` | `Verification` | 保存需要取得和检查的审批、日志、测试报告、记录或其他制品。 |

核心关系为：

```text
Source
  -> Provision
  -> Requirement
  -> Control
  -> Verification
       -> EvidenceRequirement

Decision -> Requirement / Control
```

关系约束：

- 一个 `Provision` 只属于一个 `Source`。
- 一个 `Requirement` 可以引用多个 `Provision`，一个 `Provision` 也可以支持多个 `Requirement`。
- `Requirement` 与 `Control`、`Control` 与 `Verification` 都允许多对多关系。
- `Decision` 只记录人工决定，并明确指向相关 `Requirement` 或 `Control`。
- 每种核心对象都需要稳定标识；具体标识格式在字段设计时确认。
- 对象使用明确的类型化引用字段，不使用无法限制目标类型的通用关系数组。

## 示例

ICT 变更职责分离使用以下对象形成闭环：

```text
Source
  Regulation (EU) 2024/1774

Provision
  Article 17(1)(b)

Requirement
  变更批准职能与申请、实施职能保持独立
  Applicability: 完整 ICT 风险管理框架

Control
  requester、approver、implementer 权限分离
  ImplementationRule: 同一人员不能同时承担冲突角色

Verification
  检查变更记录中的角色身份和审批顺序
  EvidenceRequirement: 变更单、审批记录、操作日志
```

如需确认某类机构是否适用该要求，使用 `Decision` 记录确认人、结论、理由、依据和有效时间。

## 影响

- Schema 设计围绕六种核心对象展开，同时校验三个内嵌结构。
- 适用范围、实施规则和证据要求暂时不能被独立引用或单独发布。
- Skills、任务模板、知识地图、检索索引和发布清单属于使用或发布结果，不进入 v0.1 核心知识模型。
- 后续真实内容出现独立复用、独立审批或独立生命周期需求时，可以通过新的设计决定将内嵌结构升级为核心对象。
- 下一步逐类确认通用字段、类型专属字段、状态和引用规则。工程候选 Schema 和模型夹具可以在确认期间用于暴露结构问题；正式知识对象目录在确认完成后创建。
