# EMI Knowledge v0.3.0 独立使用验收

- 验收日期：2026-09-07
- 验收版本：`v0.3.0`
- 发布级别：`engineering_baseline`
- 内容摘要：`6adba77ba28d33c8d7ed02b13848b3bb9114f6b13209fe274bb76c53c6dbdad4`
- 验收范围：人员阅读、Agent 上下文、产品查询、Topic 隔离和组合发布

## 验收环境

验收直接使用 [`releases/v0.3.0`](../../releases/v0.3.0/README.md) 中的固定文件。人员路径使用生成的 Markdown，Agent 路径使用 `agent-context.json`，产品路径通过固定版本读取器使用 `knowledge.json`。本轮未接入 EMI Harness、真实大模型、数据库、向量检索、机构系统、生产灾备环境或监管渠道。

## 自动化检查

执行命令：

```bash
npm run check
npm run release:v0.3
npm run example:query -- req-full-recovery-objectives v0.3.0
npm run release:v0.2
npm run release:v0.1
```

最终 33 项自动化测试全部通过，覆盖：

- `v0.1.0`、`v0.2.0` 与 `v0.3.0` 的确定性生成和仓库制品漂移检查。
- Topic Schema、批准状态、入口闭包、上下文边界、未知 Topic 和非批准 Topic 拒绝。
- 业务连续性专题 23 项 Requirement 到 10 项 Control、10 项 Verification 和 20 类 EvidenceRequirement 的完整链。
- 三个固定版本的 Schema 注册、版本锁定、关系查询和 Manifest Schema 路径解析。
- 人员、Agent 和产品制品的内容摘要、Topic、对象和待确认项一致性。
- 历史 `v0.1.0` 与 `v0.2.0` 发布文件逐字节保持不变。

## 验收修正

真实 CLI 查询发现示例程序曾根据发布版本推断 Schema 目录，导致 `v0.3.0` 尝试读取不存在的 `schemas/v0.3`。读取流程现改为从固定发布 Manifest 解析知识对象、Topic 和发布制品 Schema 路径，并拒绝指向仓库外部的路径。自动化测试已覆盖 `v0.3.0` 复用 `0.2.0` 发布制品 Schema 的情况。

## 剩余限制

- 尚未由外部法律顾问、具体机构合规人员或主管机关确认法律适用性。
- 尚未使用真实 EMI 的职能清单、BIA、RTO、RPO、系统配置、连续性计划、备份、演练和运行证据完成业务验收。
- Agent 验收覆盖确定性上下文和回答契约，未覆盖真实模型的准确性、稳定性、长上下文行为和工具调用。
- EMD2 Article 9(1) 豁免、microenterprise 状态、机构恢复参数、内部职责和风险接受仍需有权人员确认。
- Malta AX05、Minimum Requirements Guidelines、Addendum 及可能存在的连续性材料模板需要在实际任务中核对。
- DORA Chapter IV 通用数字运营韧性测试、TLPT 和 Chapter V ICT 第三方风险尚未形成独立完整专题。

## 结论

`v0.3.0` 通过独立工程使用验收，可以作为人员、Agent 和产品后续试用的固定 DORA ICT 变更、事件与业务连续性工程基线。该结论不包含具体机构法律适用性、灾难声明、恢复完成、风险接受、合规状态或生产就绪判断。
