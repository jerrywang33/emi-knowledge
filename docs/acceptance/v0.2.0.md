- 验收日期：2026-09-07
- 验收版本：`v0.2.0`
- 发布级别：`engineering_baseline`

## 验收环境

验收直接使用 [`releases/v0.2.0`](../../releases/v0.2.0/README.md) 中的固定文件。人员路径使用生成的 Markdown，Agent 路径使用 `agent-context.json`，产品路径通过固定版本读取器使用 `knowledge.json`。本轮未接入 EMI Harness、真实大模型、数据库、向量检索、机构系统或监管报送渠道。

## 自动化检查

执行命令：

```bash
npm run check
npm run release:v0.2
npm run example:query -- req-major-incident-determination v0.2.0
npm run release:v0.1
```

最终 28 项自动化测试全部通过，覆盖：

- `v0.1.0` 与 `v0.2.0` 确定性生成和仓库制品漂移检查。
- Topic Schema、批准状态、入口闭包、上下文边界、未知 Topic 和非批准 Topic 拒绝。
- 66 项事件 Requirement 到 13 项 Control、13 项 Verification 和 EvidenceRequirement 的完整链。
- `0.1.0` 与 `0.2.0` 固定版本读取、Topic Schema 注册、版本锁定和关系查询。
- 人员、Agent 和产品制品的内容摘要、对象和待确认项一致性。
- 历史 `v0.1.0` 内容摘要继续保持 `572112de29790efa365b5fd25b764ada419fde99c34ee59e38be881dfb88f3e7`。

## 验收修正

本轮根据实际生成与读取结果完成四项工程修正：

1. Topic 校验与发布器共用同一个闭包计算，明确入口主链和补充上下文的检查边界。
2. 固定版本读取器支持 `0.2.0` 制品，并要求消费者显式提供 Topic Schema。
3. 查询示例支持声明发布版本，避免固定读取历史 `v0.1.0`。
4. Topic 型人员文档正确显示 `all`、`include`、`exclude`、`not_applicable` 和 `unknown` 适用分支。

## 剩余限制

- 尚未由外部法律顾问、具体机构合规人员或主管机关确认法律适用性。
- 尚未使用真实 EMI 的组织角色、系统配置、事件记录、报告材料和运行证据完成业务验收。
- Agent 验收覆盖确定性上下文和回答契约，未覆盖真实模型的准确性、稳定性、长上下文行为和工具调用。
- Malta 非 ICT 支付事件入口、年度成本损失请求方式和 MFSA 动态操作材料仍需在实际任务中确认。
- 业务连续性、韧性测试和 ICT 第三方风险尚未形成独立完整专题。

## 结论

`v0.2.0` 通过独立工程使用验收，可以作为人员、Agent 和产品后续试用的固定 DORA ICT 变更与事件管理工程基线。该结论不包含具体机构法律适用性、事件报告决定、合规状态或生产就绪判断。
