## 目标

V1.0 形成面向 Malta 母国 EMI、支持后续 EU/EEA 展业的核心监管与工程知识基线。详细法规范围、横向维度、排除项和六个验收场景以[根 README 的 V1.0 范围](../../README.md#v10-范围)为准。

## EMI 业务知识建设

首批范围与文档职责见 [EMI & Payments 文档](../../docs/emi-payments/README.md)。保留现有五个领域、六类核心对象和目录结构，业务说明放入 `docs/emi-payments/`，不新增顶层分类或 Schema。

先建设“支付处理与异常”，再根据实际使用确定客户与账户、电子货币与资金流转、账务与对账的顺序。这是 EMI 业务说明内部的建设顺序；其他领域的首个 Topic 及整体发布顺序仍需确认。

用户已确认普通 SEPA 欧元转账（SCT、非即时转账）作为首个学习样例。具体机构产品、PSP 与清算接入尚未选择，不将学习范围当作产品决定。

| 步骤 | 交付物与完成条件 | 状态 |
| --- | --- | --- |
| 1. 确认组织方式 | 四个业务专题、文档位置、内容结构和首个建设对象写入 README 与领域说明。 | 已完成 |
| 2. 确认支付范围与来源 | 明确学习场景、参与方与排除项，完成指定来源复核；实际产品与渠道决定单独记录。 | 学习范围已确认；EPC 版本、指定章节和 PDF 摘要已核对，待维护者复核；法律适用性复核未完成 |
| 3. 编写业务说明 | 写清概念、正常流程、资金与记录关系、异常处理和设计取舍；示例与已确认规则分别标明。 | 初稿已完成，待逐节审查 |
| 4. 关联知识对象 | 引用适用的 Requirement、Control、Verification 和 Decision；尚未建设或确认的关系列为缺口，不虚构对象或适用结论。 | 已关联 8 个固定版本 DORA 对象；SCT 正式知识链与跨领域映射待建设 |
| 5. 检查使用结果 | 用正常、重复请求、超时与结果未知、记录不一致等范围内案例检查说明，保留未覆盖分支和人工决定点。 | 已准备 10 个走读用例；人员、Agent 与渠道独立执行未开始 |

本轮交付为[支付处理与异常草案](../../docs/emi-payments/payment-processing-and-exceptions.md)和[来源核对记录](../../docs/sources/emi-payments-sct-source-review.md)。本轮不新增 Schema、Skill、受控 Topic 或场景包。

正文审查和案例检查完成前不宣称业务专题完成。业务说明不会自动进入现有 JSON 发布；是否纳入后续发布、如何固定文档版本以及需要哪些新知识对象，在首份说明可审查后单独确认。当前固定发布继续为 `v0.3.0`。

## 规划规则

1. 每次只确认并建设一份能够独立检查的业务说明或一个受控 Topic。
2. 每个 Topic 先完成来源复核和覆盖矩阵，再建立受控知识对象。
3. 共用对象只维护一次，通过 Topic 引用，不按法规复制。
4. 每个中间发布继续固定 Topic、对象修订、来源输入、内容摘要和限制。
5. `v1.0.0` 发布前完成六个跨领域场景和至少一个脱敏真实 EMI 产品范围的工程验收。

其余领域的具体里程碑、版本编号和顺序将在相应 Topic 确认后加入本目录，不提前创建空计划文件。
